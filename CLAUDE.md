# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

OTC Learn — a React Native 0.86 / Expo SDK 57 mobile learning app for OTC
derivatives. Redux Toolkit, TypeScript strict, offline-first, no backend and no
sign-up. `README.md` covers the product and release story in depth; this file is
the working reference.

## Commands

```bash
npm run verify        # type-check + lint + format:check + test — the CI gate
npm test              # jest
npm run test:coverage # thresholds: 70% lines/statements, 60% branches/functions
npm run type-check    # tsc --noEmit
npm run lint:fix
npm run format        # prettier, printWidth 84

# A single suite, or a single test by name:
npx jest __tests__/store/quizSlice.test.ts
npx jest -t 'resets the streak after a gap'

npm start             # Metro alone
npm run android       # prebuild + native debug build onto a device/emulator
npm run web           # browser preview, fastest loop for pure UI work
```

`.github/workflows/ci.yml` runs `npm run verify` on push and PR to `main`. Run it
before declaring work done.

**Expo Go cannot run this app** — `expo-updates`, `@sentry/react-native`,
`react-native-svg`, `react-native-reanimated`, `expo-haptics` and
`expo-notifications` are native modules it does not bundle, so `npm run android`
does a real `expo run:android` build (slow first time, incremental after). If
Gradle reports "SDK location not found", export `ANDROID_HOME`; if the emulator
cannot reach Metro, `adb reverse tcp:8081 tcp:8081`. `android/` and `ios/` are
generated by `expo prebuild` and gitignored — never hand-edit them; change
`app.json` instead.

## Architecture

### Navigation is Redux state, not a navigator

`app.currentScreen` is the single source of truth and `RootNavigator` is a switch
over it (`src/navigation/RootNavigator.tsx`). There is no React Navigation
dependency and adding one would duplicate state that every screen already reads
from `appSlice`. Consequences to keep in mind:

- Transitions go through `useNavigation()`, never a raw `dispatch(navigateTo…)` —
  the hook also performs the clean-up each transition implies (`resetQuiz`) and
  emits the analytics event.
- The tab bar is a control over the same state, not a second navigator.
  `currentTab` records which tab a detail screen was reached from, so the bar
  keeps highlighting where you came from; `showsTabBar()` hides it on
  lesson/quiz/results, where a mis-tap would discard a part-finished quiz.
- The three freebies a navigator would have given us are wired manually in
  `RootNavigator`: `useHardwareBack` (Android back button), `useDeepLinks`, and
  the tab bar itself. Links are `otclearn://` + `category/<id>`, `product/<id>`
  (the product page), `lesson/<id>`, `review`, `profile`, `glossary` — parsed by
  `navigation/linking.ts` and validated against the catalogue.

### Data flow

`App.tsx` hydrates before recording: `hydrateApp` resolves first (running any
pending storage migration), then `recordActivity`, so the streak rules see the
stored `lastActivityDate` rather than `null`. Persistence is confined to
`utils/storage.ts` — reads swallow failures and malformed payloads into
`null`/`[]`/`{}` so a corrupt cache can never block launch. Slices stay pure;
anything touching AsyncStorage is a thunk in `store/thunks/`.

`RootState` in `store/index.ts` is declared explicitly rather than inferred from
`store.getState()`, because the thunks import it for `getState` typing and
inference would make that circular. `createStore()` builds isolated stores for
tests.

### Progress is mastery, not a completed flag

`utils/mastery.ts` holds the rule: mastery moves *toward* each session's score at
a 0.35 learning rate rather than being replaced by it, so one lucky run cannot
mark a product learned and one bad run cannot undo weeks. 70 is the completion
threshold. Everything else — category rings, headline percentage, achievements —
derives from that number, so don't reintroduce a boolean beside it.

`utils/review.ts` schedules missed questions on a 1/4/10-day ladder and then an
SM-2 ease factor capped at 120 days; three clean passes retire an item. Both
modules are pure and take `now`/`rng` as arguments, because scheduling and
shuffling fail silently — a wrong interval or a lost answer index never throws.

### Content is data, and ids are a persisted schema

Content lives in `src/data/catalogue/`, one file per asset class, composed by
`src/data/products.ts`. Mastery records are keyed by product id and the review
queue by question id, so **renaming either silently discards a user's progress**
— add freely, rename only with a migration.

Each product carries a summary, five lesson steps with optional callouts, six key
terms, a worked example, an in-practice note, related products, and a bank of 12
questions mixing `kind: 'boolean'` and `kind: 'choice'`. A quiz draws a subset of
that bank (`utils/quizSession.ts`), weighted toward questions you have missed or
not seen, so no two sittings are the same paper.

Nothing hardcodes step or question counts; screens read `product.lessons.length`
and `quiz.questions.length`. Adding content is a data change alone, and tests
derive expected counts from the catalogue rather than from literals.
`__tests__/data/catalogue.test.ts` enforces the structural invariants — bank
size, four distinct options, `correctIndex` in range, all five steps covered, a
spread of difficulty, resolvable `relatedProductIds` — and new content must
satisfy it.

**Accuracy is the product.** This is financial education; a wrong claim teaches
someone something false about a market they may trade in. Post-LIBOR conventions
apply (SOFR/SONIA/€STR). Verify arithmetic in worked examples by doing it.

### Side-effect facades

All instrumentation goes through `track()` in `utils/analytics.ts`, a typed
no-op sink. `utils/errorReporting.ts` installs a Sentry adapter only when
`EXPO_PUBLIC_SENTRY_DSN` is non-empty; v1.1 ships with no DSN, so the app makes
exactly one network call (the `expo-updates` launch check). Add new events to the
`AnalyticsEvent` union rather than calling a provider directly.

`EXPO_PUBLIC_*` values are inlined by Babel at build time, not read at runtime —
which is why `initErrorReporting` takes its config as an argument with env values
only as defaults, and why tests cannot exercise it by mutating `process.env`.

Haptics go through `utils/haptics.ts`, which takes the user's setting as an
argument so the preference is enforced in one place, swallows its own failures
(a device with no vibrator rejects the call), and no-ops off-device.

Notifications go through `utils/notifications.ts`. The OS is the source of truth:
permission can be revoked in system settings at any time, so `syncReminder` runs
on launch and repairs or reports the mismatch rather than letting the toggle lie.

### Theme

`src/theme/` is the only place colour, type, spacing, radius and shadow values
live; screens import tokens, never literals. Colours are stored as sRGB hex with
the design's source OKLCH in a comment beside each — RN's `StyleSheet` cannot
parse OKLCH, so keep both in step when changing one.

## Conventions

- **Relative imports only.** Path aliases were deliberately removed so
  `babel.config.js`, `tsconfig.json` and `jest.config.js` don't have to stay in
  sync. Don't reintroduce them.
- Named exports everywhere; `default` is reserved for `App` and slice reducers.
- Screens live in `src/screens/<Name>/`, with sub-components that only that
  screen uses under its local `components/`. Shared pieces go in
  `src/components/ui/` (primitives) or `common/` (layout, error boundary).
- `StyleSheet.create` sits at the bottom of the file; components take a `testID`
  prop where tests need a handle.
- Comments explain *why* a non-obvious choice was made, not what the code does —
  match that bar. Prose in this repo (comments, docs, commit subjects) is written
  in British English, sentence case, and full sentences.
- `noUnusedLocals`/`noUnusedParameters` are on; prefix intentionally unused
  bindings with `_`.

## Tests

`__tests__/` mirrors `src/`; only `*.test.ts(x)` files are collected, so
`__tests__/helpers/` is free for utilities. Render through
`renderWithStore(...)` from `__tests__/helpers/renderWithStore.tsx` — it is
`async` and must be awaited, and it supplies a fresh store plus stubbed
safe-area metrics (pass an existing `store` to carry state across renders in a
flow test). AsyncStorage, `expo-splash-screen`, the Google Fonts hook,
`expo-haptics`, `expo-notifications` and `react-native-reanimated` are mocked
globally in `jest.setup.js`. The reanimated mock is hand-written: requiring the
library's own `mock` entry point pulls in `react-native-worklets`, which dies
looking for a native install under Jest.

Prefer driving `RootNavigator` through real interactions (see
`__tests__/integration/userFlow.test.tsx`) over asserting on reducers alone when
the behaviour spans screens.

Quiz papers are drawn at random, so a test must never assume which questions —
or which question *kind* — it will get. Read the drawn paper from the store and
branch, or seed `buildSession` with `seededRng` from `utils/shuffle.ts`.

## Release notes worth knowing

- Signing is EAS-managed; there is no keystore in this repo and there should
  never be one.
- `runtimeVersion` policy is `appVersion`, one EAS Update channel per build
  profile. A JS-only fix ships via `eas update --channel production`; anything
  touching native code (including switching Sentry on) needs a new build.
  Bumping `version` in `app.json` starts a new runtime version and cuts older
  installs off from updates.
- `assets/` is generated by `node scripts/generate-assets.js`; screenshots by
  `scripts/capture-screenshots.sh`, which drives the app via deep links.
- The daily reminder means the app now declares `POST_NOTIFICATIONS`,
  `RECEIVE_BOOT_COMPLETED` and `VIBRATE` (the last for haptics). `app.json`
  blocks the Firebase Cloud Messaging baggage `expo-notifications` drags in.
  **`expo prebuild` cannot show you the real permission list** — library
  manifests merge during the Gradle build, so check the artifact:
  `aapt2 dump permissions build.apk | grep uses-permission`.
- `PRODUCTION_READINESS.md` tracks what is still outstanding before submission;
  `ANDROID_DEPLOYMENT_COMPLETE.md` is the store walkthrough (its Phase 4
  keystore section does not apply — EAS owns signing).
- iOS is unverified. v1.1 targets Android; iOS scripts and config exist but no
  iOS build has been run.
